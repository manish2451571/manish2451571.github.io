# ExpenseTracker

A full-stack personal finance tracker with user authentication, transaction management, and spending charts. Built with Flask (Python) + vanilla JS.

---

## Features

- Register / login with JWT authentication
- Add, view, and delete income & expense transactions
- Filter by month, search by title or category
- Spending breakdown by category (doughnut chart)
- Monthly income vs expense overview (bar chart)
- Fully responsive dark UI

## Local Development

### 1. Clone and set up

```bash
git clone <your-repo-url>
cd expanse-tracker
```

### 2. Create a virtual environment

```bash
python -m venv venv

# Windows
venv\Scripts\activate

# macOS / Linux
source venv/bin/activate
```

### 3. Install dependencies

```bash
cd Backend
pip install -r requirements.txt
```

### 4. Configure environment variables

```bash
# Copy the example file
cp .env.example .env

# Open .env and set your values (JWT_SECRET is pre-generated if you cloned fresh)
```

Required variables:

| Variable | Description |
|---|---|
| `JWT_SECRET` | Random secret for signing JWT tokens. Generate with `python -c "import secrets; print(secrets.token_hex(32))"` |
| `FRONTEND_ORIGIN` | Allowed CORS origin. Use `http://localhost:5000` locally |
| `FLASK_DEBUG` | Set to `1` for debug mode locally. **Never `1` in production** |
| `PORT` | Port to listen on. Defaults to `5000` |

### 5. Run the server

```bash
# From the Backend/ directory
gunicorn server:app

# Or for development with auto-reload
FLASK_DEBUG=1 python server.py
```

Open [http://localhost:5000](http://localhost:5000) — the app loads automatically.

## Deployment

### Render (recommended)

1. Push the repo to GitHub
2. Go to [render.com](https://render.com) → **New → Web Service** → connect your repo
3. Render detects `render.yaml` automatically — click **Apply**
4. After the first deploy, go to **Environment** in the Render dashboard and set:
   - `FRONTEND_ORIGIN` → your Render app URL (e.g. `https://expanse-tracker.onrender.com`)
   - `JWT_SECRET` is auto-generated by Render via `generateValue: true`
5. Redeploy — done

### Railway

1. Push the repo to GitHub
2. Go to [railway.app](https://railway.app) → **New Project → Deploy from GitHub Repo**
3. Railway detects `railway.toml` automatically
4. Go to **Variables** and add:
   - `JWT_SECRET` → `python -c "import secrets; print(secrets.token_hex(32))"`
   - `FRONTEND_ORIGIN` → your Railway app URL
5. Deploy — done

### Heroku

```bash
heroku create expanse-tracker
heroku config:set JWT_SECRET=$(python -c "import secrets; print(secrets.token_hex(32))")
heroku config:set FRONTEND_ORIGIN=https://expanse-tracker.herokuapp.com
heroku config:set FLASK_DEBUG=0
git push heroku main
```

## Environment Variables Reference

| Variable | Required | Default | Description |
|---|---|---|---|
| `JWT_SECRET` | **Yes** | `dev-only-change-me` | Secret key for JWT signing. Must be set in production |
| `FRONTEND_ORIGIN` | **Yes (prod)** | `*` | Allowed CORS origin. Wildcard is unsafe in production |
| `FLASK_DEBUG` | No | `0` | Enable Werkzeug debugger. Never use `1` in production |
| `PORT` | No | `5000` | Server port. Injected automatically by most platforms |

---

## Security Notes

- Passwords are hashed with PBKDF2+salt via `werkzeug.security`
- All API routes are protected with JWT Bearer token authentication
- SQL queries use parameterized statements — no SQL injection risk
- Static files are served only from the `Frontend/` directory — no path traversal
- HTML output is escaped in the frontend to prevent stored XSS
- `FLASK_DEBUG` is off by default — the Werkzeug debugger is a remote code execution risk if left on
